# VLESS REALITY для Happ

Комплект запускает Xray-core в Docker на Linux VPS и создаёт одну ссылку `vless://` для Happ. Профиль использует VLESS поверх TCP с REALITY и XTLS Vision. Своего домена и TLS-сертификата для VPS не требуется.

## Рабочий профиль

В проверенной установке SSH доступен на TCP-порту `22`, Xray — на `8443`, а цель REALITY — `www.microsoft.com:443`. В Happ использован TLS-отпечаток `firefox`. С ним HTTPS-запрос через локальный SOCKS-прокси Happ вернул публичный IPv4 VPS. С исходным `fp=chrome` тот же запрос завершался по тайм-ауту. Точная причина обрыва при рукопожатии осталась неизвестной.

Если контейнер уже развёрнут, переходите к разделу [Импорт рабочего профиля в Happ](#импорт-рабочего-профиля-в-happ).

## Развёртывание через GitHub Actions

Workflow находится в `.github/workflows/deploy.yml`. При установке из архива поместите содержимое папки `happ-vless`, включая `.github`, в корень репозитория. Workflow запускается при изменении файлов деплоя в ветке `main`. Ручной запуск доступен в **Actions → Deploy VLESS to VPS → Run workflow** для той же ветки.

### SSH-доступ на VPS

На VPS нужны Docker Engine, Python 3.9+, Bash и `flock` из пакета `util-linux`. Включите SSH и убедитесь, что пользователь деплоя может выполнить `docker info` без `sudo`. Для существующей установки используйте того же пользователя и каталог `~/happ-vless`. В этом каталоге сохраняются `state`, действующий UUID и ключи REALITY. Для этой установки разрешите входящий `8443/tcp` в сетевом экране провайдера. Если на Ubuntu уже активен UFW, добавьте правило командой `sudo ufw allow 8443/tcp`. Убедитесь, что доступ по SSH сохраняется.

Для нового сервера создайте отдельный SSH-ключ для CI на своём компьютере. Если ключ уже настроен, используйте существующий.

```bash
ssh-keygen -t ed25519 -N '' -f ~/.ssh/github-actions-vps -C happ-vless-github-actions
ssh -p 22 deploy@VPS_HOST 'umask 077; mkdir -p ~/.ssh; cat >> ~/.ssh/authorized_keys' < ~/.ssh/github-actions-vps.pub
```

Замените `deploy`, `VPS_HOST` и `22` на свои данные. Для отдельного ключа в `authorized_keys` можно добавить префикс `restrict`. Он запрещает проброс портов, agent forwarding и выделение терминала, сохраняя выполнение SSH-команд и передачу файлов.

Для проверки подлинности сервера получите его публичный SSH-ключ из доверенной консоли провайдера или уже проверенной SSH-сессии. Выполните команду на VPS.

```bash
printf 'happ-vless-vps %s\n' "$(sudo cut -d ' ' -f1,2 /etc/ssh/ssh_host_ed25519_key.pub)"
```

### Настройки репозитория

Откройте **Settings → Secrets and variables → Actions**.

| Secrets | Значение |
| --- | --- |
| `VPN_SSH_PRIVATE_KEY` | Полное содержимое `~/.ssh/github-actions-vps`, включая первую и последнюю строки. |
| `VPN_SSH_KNOWN_HOSTS` | Строка из команды выше, начиная с `happ-vless-vps ssh-ed25519`. |

| Variables | Значение |
| --- | --- |
| `VPN_SSH_HOST` | IPv4 или DNS-имя VPS для SSH. Обязательно. |
| `VPN_SSH_USER` | Пользователь SSH с доступом к Docker. Обязательно. |
| `VPN_SSH_PORT` | SSH-порт. По умолчанию `22`. |
| `VPN_PUBLIC_HOST` | Публичный IPv4 или DNS-имя для Happ. По умолчанию совпадает с `VPN_SSH_HOST`. |
| `VPN_PORT` | Укажите `8443` для этой установки. При пустом значении установщик выбирает `443`. |
| `VPN_SNI` | Имя цели REALITY. По умолчанию `www.microsoft.com`. |
| `VPN_NAME` | Имя в Happ. По умолчанию `Мой VPN`. |

Если профиль уже есть, заполните переменные теми же публичным адресом, портом, SNI и названием, с которыми он был создан. При смене версии образа в `happ-vless.py` деплой сначала проверяет конфиг новым Xray, потом перезапускает контейнер. Если новый контейнер не проходит проверку запуска, установщик восстанавливает предыдущий.

## Импорт рабочего профиля в Happ

После успешного деплоя выполните команду **на Mac**. Подставьте публичный адрес своего VPS. Если ваш SSH-ключ имеет другое имя, поправьте путь после `-i`.

```bash
VPS_HOST=203.0.113.10
ssh -p 22 -i ~/.ssh/github-actions-vps "deploy@$VPS_HOST" \
  'python3 ~/happ-vless/happ-vless.py link' | \
  sed 's/fp=chrome/fp=firefox/; s/#.*/#my_vpn_firefox/' | pbcopy
```

Установщик хранит исходную ссылку с `fp=chrome`. Команда копирует в буфер вариант с `fp=firefox` и именем `my_vpn_firefox`, сохраняя UUID, публичный ключ REALITY, Short ID и SNI. Этот вариант можно импортировать повторно без перезапуска контейнера. Ссылка даёт доступ к VPN, храните её как пароль.

В Happ нажмите **+ → Добавить из буфера обмена**, выберите **my_vpn_firefox** и включите подключение.

## Проверка с Mac

Сначала проверьте передачу HTTPS через локальный SOCKS-порт Happ. Команда задаёт IP назначения явно, чтобы результат не зависел от DNS на Mac.

```bash
curl -fsS --noproxy '' --proxy socks5://127.0.0.1:10808 \
  --resolve one.one.one.one:443:1.1.1.1 --max-time 15 \
  https://one.one.one.one/cdn-cgi/trace | grep '^ip='
```

Ожидаемый результат — `ip=<публичный IPv4 вашего VPS>`. Затем проверьте обычный запрос по доменному имени без явного указания прокси.

```bash
curl -4 -fsS --max-time 10 https://api.ipify.org && echo
```

Если оба запроса показывают адрес VPS, оба пути работают. Если адрес VPS вернул только первый запрос, VLESS уже передаёт трафик. Для второго проверьте режим туннеля, правила маршрутизации и DNS в Happ.

## Ручная установка

Понадобятся Linux VPS с публичным IPv4, рабочий Docker Engine, Python 3.9+ и свободный входящий TCP-порт. Скрипт использует официальный образ `ghcr.io/xtls/xray-core:26.11.9`. При первом запуске Docker скачает его из GHCR.

1. Перенесите `happ-vless.zip` на VPS, распакуйте и войдите в папку.
2. Разрешите входящий `8443/tcp` в сетевом экране провайдера VPS. Если у сервера есть отдельный сетевой экран, учитывайте правила публикации портов Docker.
3. Запустите команды на VPS. Замените `203.0.113.10` на публичный IPv4 своего VPS или на домен, A-запись которого указывает на этот IPv4.

```bash
unzip happ-vless.zip
cd happ-vless
python3 happ-vless.py install 203.0.113.10 --port 8443
```

Если Docker доступен вашему пользователю, можете выполнять все команды без `sudo`. Используйте тот же способ в последующих запусках.

Для своего названия профиля добавьте `--name "Мой VPS"`. Если установили проект в другой каталог, используйте его путь в команде импорта.

## Обслуживание

Выполняйте команды на VPS под пользователем деплоя. Команда `link` выводит исходный профиль. Для повторного импорта рабочего варианта используйте команду с `pbcopy` выше.

```bash
cd ~/happ-vless
python3 happ-vless.py link
docker logs --tail 100 happ-vless
docker restart happ-vless
docker stop happ-vless
docker start happ-vless
```

Команда `install` с теми же параметрами повторно выдаёт ту же ссылку, а при необходимости запускает остановленный контейнер. Стратегия Docker `unless-stopped` запускает контейнер после перезагрузки VPS, если он ранее не был остановлен вручную. Папку `state` храните вместе с установщиком. В ней находятся серверный ключ, настройки и клиентская ссылка.

## Если Happ не подключается

- Убедитесь, что в ссылке указан публичный адрес VPS и нужный порт, а входящий TCP разрешён в сетевом экране провайдера. Проверяйте из внешней сети.
- Проверьте состояние и логи контейнера командами `sudo docker ps -a --filter name=happ-vless` и `sudo docker logs --tail 100 happ-vless`.
- По умолчанию целью REALITY служит `www.microsoft.com:443`. VPS должен иметь доступ к ней по TCP и поддерживать корректное системное время. При первой установке цель можно выбрать через `--sni имя.домена`. Выбранный HTTPS-сервер должен поддерживать TLS 1.3 и HTTP/2. Имя цели REALITY и публичный адрес VPS задаются отдельно.
